💳 Pagament online integrat dins l'app v2.1.10 · NOU

Nou botó "⬆ Millora el plan" dins ⚙️ Configuración del client. Flux automatitzat:
  1. Client clica el botó → l'app crida POST /api/payments/create-subscription amb el seu installId
  2. Backend obre sessió Stripe Checkout en mode subscription (auto-renewal) i retorna la URL
  3. App obre la URL al navegador del client (targeta / Bizum / SEPA)
  4. Un cop pagat, Stripe envia webhook checkout.session.completed → backend crea clau JWT PREMIUM amb expires_at = current_period_end
  5. A partir d'aquí, Stripe cobra automàticament cada mes/any. Cada invoice.paid renova la clau JWT extenent l'expiració
  6. Si el pagament falla (invoice.payment_failed) → licencia queda en estat past_due
  7. Si el client cancel·la (customer.subscription.deleted) → licencia queda en estat canceled però funciona fins current_period_end

🧾 Portal de Client Stripe (self-service) v2.1.10 · NOU

11. Protecció del codi

Què tens protegit

  • ✅ JavaScript obfuscator alt (string arrays + control flow flattening)
  • ✅ Empaquetat ASAR dins l'.exe
  • ✅ DevTools desactivats (F12, Ctrl+Shift+I, Ctrl+U, botó dret)
  • ✅ JWT amb secret al servidor (impossible generar claus vàlides sense el teu LICENSE_SECRET)
  • ✅ Master Key personal no evident
  • ✅ HWID Lock — llicència vinculada al PC del client (impedeix pirateig entre centres)

🔒 HWID Lock detallat

Com actua:
  1. Client instal·la l'app i activa el JWT al seu PC (PC A)
  2. Backend rep HWID i el guarda vinculat a la llicència (binding)
  3. Cada verify posterior compara HWID
  4. Si HWID diferent → app mostra "Aquesta llicència està vinculada a un altre ordinador. Contacta amb el proveïdor per fer el canvi."
Quan un client canvia de PC legítimament:
  1. Client et contacta
  2. Vés a /admin, localitza la seva llicència
  3. Clica 🔓 (taronja) — Desbloquejar HWID
  4. Confirmes → el HWID guardat es buida
  5. Client obre l'app al nou PC → nou binding automàtic
Comptador de resets: el sistema guarda hwid_reset_count. Si un client demana 3+ canvis en 6 mesos, sospita.
💡 Client amb 2 PCs (oficina+casa): genera 2 llicències separades amb Install IDs diferents. Cobra un extra (+50%). Respecta el HWID lock i tens ingressos majors.

12. Preguntes freqüents

Un client canvia d'ordinador, què faig?

Vés al admin, localitza la seva llicència, clica 🔓 Desbloquejar HWID. Confirmes i llest — al nou PC quedarà vinculada automàticament.

Com faig una promoció (mesos gratis)?

Al aprovar, indica una durada personalitzada (per exemple 90 dies gratis). El JWT porta el exp i caduca sol.
Amb Stripe Subscriptions: crea codis de promoció al Dashboard.

Cost mensual del sistema en producció?

  • Domini: ~10€/any (~1€/mes)
  • Emergent Deploy: ~15€/mes
  • Google Workspace: ~5€/mes (opcional)
  • Stripe: 0€ fix, només comissió (~1,4%)
  • Twilio: ~1$/mes + ~0,05€/SMS
  • Resend: gratis fins 3000 emails/mes
Total fix: ~20-25€/mes. Amb 1 client STD anual (299,90€) ja tens l'any cobert.

Puc revendre a 100+ centres alhora?

Sí, escalable. Cada centre té JWT únic + HWID únic. Backend gestiona verificacions concurrents amb rate limit 60/minute per IP.

Què passa si perdo el LICENSE_SECRET?

Totes les llicències existents deixen de verificar-se. Cal regenerar el secret + regenerar tots els JWTs + reenviar-los. Fes-ne backup a un gestor de contrasenyes.

Per què hi ha "flashos" en obrir el preview?

El servidor preview d'Emergent s'adorm després d'uns minuts sense visites. Quan hi tornes triga 30-60s a despertar-se. Un cop facis el deploy a producció (15€/mes) el servidor NO s'adorm mai i el problema desapareix del tot.

Puc revendre a més d'un centre alhora?

Absolutament. Cada centre té la seva llicència JWT única. Tot el sistema està preparat per escalar.

13. 🆘 Errors 404 · Sistema auto-reparació

Bones notícies (v2.1.6): el sistema ara s'auto-repara sol. Ja no cal editar cap fitxer, ni res. Els 404 del SMS/Cites es solucionen automàticament sense la teva intervenció.

🤖 Com funciona (per si has de saber-ho)

Cada cop que el backend arrenca...
  1. Detecta la seva pròpia URL (via env var d'Emergent).
  2. Fa commit del fitxer api-endpoint.json al repo GitHub Medicarplus/medicarplus-releases amb aquesta URL.
  3. El fitxer és accessible a raw.githubusercontent.com/Medicarplus/medicarplus-releases/main/api-endpoint.json
Cada cop que l'app Electron d'un client s'obre...
  1. Consulta aquest fitxer JSON (URL estable de GitHub, mai canvia).
  2. Cachea la URL correcta a localStorage per 24h.
  3. Fa servir aquesta URL per a SMS, Cites, IA, llicència, etc.
Si Emergent roti la URL de preview (esdevé sol de tant en tant)...
  1. El backend arrenca a la nova URL i auto-publica el JSON amb la URL nova.
  2. L'app dels clients detecta un 404 momentàni → torna a llegir el JSON → agafa la URL nova.
  3. Zero intervenció manual per part teva. Els clients no noten res.

❌ Què fer si un client segueix veient 404 (rarament passa)

Cas 1: el client acaba d'instal·lar una versió MOLT antiga (anterior a v2.1.6). Solució: dis-li que faci ⚙️ Configuración → 🔄 Comprobar última versión. Auto-updater descarregarà v2.1.6+ i el sistema d'auto-descoberta s'activa.
Cas 2: el GitHub PAT del backend ha caducat i no pot publicar el JSON. Regenera'l:
  1. Ves a github.com/settings/tokens
  2. Nou Fine-grained PAT amb permisos Contents: Read and write al repo medicarplus-releases
  3. Copia el token nou i posa'l al backend a backend/.env com GITHUB_TOKEN=...
  4. Reinicia el backend
